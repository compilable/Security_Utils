Legacy Hash Compatibility Tool

This page is not the deterministic recovery protocol. Preserve it only for compatibility with prior outputs. Never replace an existing encrypted-volume credential without testing a second credential on disposable data.

The 1–20 control repeats legacy component hashing. It is not comparable to bcrypt cost, scrypt memory cost, or Argon2 parameters and must not be described as a universal security level.

Legacy input rules

The existing implementation trims text inputs, omits empty answers, sorts files using browser locale ordering, and combines components differently by algorithm. Those behaviors are retained solely to avoid silently breaking old outputs. New recovery records must use Recovery Protocol v1, whose byte encoding and ordering are explicit.

Offline and dependency behavior

All scripts, styles, fonts, and cryptographic libraries are bundled locally and pinned by `THIRD_PARTY_ASSETS.sha256`. The tool does not require a CDN. Web Crypto operations fail closed when secure randomness is unavailable.

Clipboard, clearing, and idle timeout

  • Copying is optional. Clipboard managers and history may retain copied values.
  • The application does not overwrite the clipboard later because that could destroy newer clipboard content.
  • Clear and idle-timeout actions clear visible fields only. Browser/JavaScript memory erasure is not guaranteed.
  • Mouse movement does not reset the idle timer; clicks, keyboard input, and form changes do.

Security answers

Answers contribute only their actual unpredictability. Familiar or discoverable answers do not become high entropy because they are hashed.

Recommended path

Use random-salt Argon2id, scrypt, or bcrypt for password verification. Use the separate versioned recovery protocol with a high-entropy seed for deterministic recovery. Use SHA-256 or SHA-512 for file integrity.
